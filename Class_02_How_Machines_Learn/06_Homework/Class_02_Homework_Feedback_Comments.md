**Bong Study Hub — Foundation Batch 2026 · Class 02: How Machines Learn**

Copy, paste, and lightly personalize (name the specific question or
idea where useful). Tone throughout is encouraging and constructive —
this is a first-year student's second assignment in the program, not
an exam. Never use these to shame a wrong answer; every comment below
treats a gap as something to build on, not a failure.

## Excellent Understanding

1. "You've clearly got the core idea — data in, patterns found, a
   model built, a prediction made. Well reasoned throughout."
2. "This is exactly the kind of thinking the class was aiming for —
   you explained it in your own words instead of just naming the
   pipeline."
3. "Strong work end to end. You didn't just recite the pipeline — you
   showed you understand *why* each stage exists."

## Good Understanding, Minor Gaps

4. "You've got the main idea — just tighten up [Q#], where the
   explanation is a little thinner than the rest of your answers."
5. "Solid overall. One small note: [specific detail] could use a
   sharper explanation, but the reasoning underneath is sound."
6. "Good grasp of the pipeline and the rule problem — the one place
   to revisit is [Q#]."

## Needs Clearer Reasoning

7. "You've got the right instinct here, but try explaining *why* —
   not just *what* happens."
8. "This answer names the right idea but doesn't yet connect it back
   to the question asked. Try walking through it step by step."
9. "Good start — now try explaining this to a friend who wasn't in
   class. What would they still be confused about?"

## Pipeline Confusion

10. "Double-check the order — Prediction comes *after* the Model is
    built, not before. Take another look at Q4."
11. "You've written 'patterns' as if it were its own stage — patterns
    are what the Learning step *finds*, not a separate box. The
    pipeline stays four stages: Data → Learning → Model → Prediction."
12. "Your explanation of Model and Prediction are swapped — Model is
    what the system builds; Prediction is what it does with something
    new."

## Rule Problem Confusion

13. "Good rules — but try connecting *why* rules become hard to write
    at scale, not just that there are a lot of them."
14. "You've named a real limitation, but see if you can describe it in
    terms of exceptions and variety, the way we did with the spam
    filter in class."
15. "This treats 'hard to write' and 'impossible to write' as the same
    thing — remember, the point isn't that rules are impossible, just
    that they stop being realistic."

## Prediction vs. Certainty Confusion

16. "Careful here — a wrong prediction doesn't mean the system wasn't
    really using Machine Learning. A prediction is a best guess, not
    a guarantee, even when it's wrong."
17. "You're treating a Machine Learning system like it should always
    be right. Revisit the cats-vs-dogs activity — even a well-trained
    system can get an ambiguous case wrong."

## Data-Quality Confusion

18. "You correctly said the system might struggle — now explain *why*
    in terms of what it did and didn't see during learning."
19. "Good instinct, but try connecting this back to the specific
    examples (small white cats, large black dogs) rather than a
    general statement about the system being 'bad.'"

## Strong Application to Everyday Example

20. "Great choice and great reasoning — you applied the pipeline to a

21. "Nice work keeping this conceptual — you didn't try to guess the

## Needs to Use Own Words

## General Encouragement / Closing

## How to Combine Comments

A typical piece of feedback uses **one positive comment + one
improvement suggestion**, per the grading workflow (see
`Class_02_Homework_Grading_Workflow.md`, Steps 5–6). For example:

> "You've clearly got the core idea — data in, patterns found, a model
> built, a prediction made. One thing to revisit: your explanation of
> Model and Prediction in Q4 are swapped — Model is what the system
> builds, Prediction is what it does with something new."

Keep total written feedback to **1–3 sentences per submission**. The
goal is a quick, warm, specific nudge — not a rewrite of the student's
work.
