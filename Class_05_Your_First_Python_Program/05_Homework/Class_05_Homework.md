## What This Assignment Is About

In class, we asked how to tell a computer something in a way it can
actually follow — since a computer never fills in a gap the way a person
listening to you would. We wrote and ran real Python code: `print()` to
display text, quotes to mark where text starts and ends, comments that
Python ignores completely, and instructions that always run top to
bottom, in order.

This assignment asks you to **read and reason about code, not just
recall facts about it**. Several questions give you a snippet of Python
and ask what it does, or what's wrong with it — exactly like the
write-run-read-fix loop from class, just on paper.

## Answers

**Q1 — Why Precise Instructions? (2 marks)**
A computer does exactly what it's told and never fills in a gap the way
a person listening would — so instructions have to be precise and
unambiguous, or the computer has no way to know what's meant. (1 mark
for stating a computer doesn't fill in gaps; 1 mark for connecting this
to needing precision/unambiguous instructions.)

**Q2 — What Does print() Do? (2 marks)**
`print(...)` displays (shows/outputs) whatever is written inside the
parentheses. Full credit for any phrasing capturing "displays/shows the
text inside the parentheses."

**Q3 — Why Quotes? (2 marks)**
Quotes mark exactly where a piece of text starts and ends, so Python
knows to treat it as literal text rather than trying to read it as more
instructions/code. Full credit for capturing "marks the boundaries of
the text" in any phrasing.

**Q4 — What Is a Comment? (2 marks)**
A comment (`#`) is a line, or part of a line, that Python completely
ignores — it produces no output and isn't treated as an instruction.
Comments are for people reading the code (a teammate, or the same
programmer later), not for the computer. (1 mark for "Python ignores
it"; 1 mark for "it's for people, not the computer.")

**Q5 — Meet Python (2 marks)**
Python is a programming language, designed to be readable — precise
enough for a computer to follow, but written in a style closer to plain
instructions than most other languages. No, it is not the only
programming language; it's one of many, each suited to different jobs.
(1 mark for identifying Python as a programming language; 1 mark for
correctly saying it isn't the only one.)

**Q6 — Predict the Output (3 marks)**
```
Roll call!
Name: Aritra
Class: Foundation Batch
```
Full credit requires the exact text, in the exact order, with correct
capitalization matching the code. (1 mark per correct line, allowing
minor transcription differences that don't change the actual words.)

**Q7 — Find the Bug (3 marks)**
The closing quote is missing after `blue.` — the line should read:
```
print("The sky is blue.")
```
(1 mark for correctly identifying the missing closing quote; 2 marks
for a correct rewritten line.)

**Q8 — Find the Bug, Again (3 marks)**
`PRINT` is capitalized, but Python only recognizes the exact lowercase
`print` — Python is case-sensitive, so `PRINT` is treated as a
completely different, unrecognized name. Corrected line:
```
print("Good morning!")
```
(1 mark for identifying the capitalization issue; 1 mark for a correct
rewritten line; 1 mark for explaining case-sensitivity in their own
words.)

**Q9 — Order Matters (3 marks)**
New output, in order:
```
Step 3: Eat breakfast
Step 2: Brush teeth
Step 1: Wake up
```
The order changed because Python runs `print()` statements exactly top
to bottom, in the order they're written — swapping the lines in the code
swaps the order of the output. (1 mark for each correctly ordered line
if listed separately, or up to 2 marks for the full correct block; 1
mark for the explanation of top-to-bottom execution.)

**Q10 — Comments Don't Run (3 marks)**
```
Welcome!
```
Only one line of output. The first line is a comment (ignored), the
`print("Welcome!")` line runs and also has a trailing comment (ignored,
doesn't affect the output), and the last line is an entire `print(...)`
call turned into a comment — so it never runs at all. Full credit
requires the student to notice the third line is commented out and
therefore produces nothing. (1 mark for the correct single line of
output; 2 marks for correctly explaining why the third `print` doesn't
run.)

**Q11 — Connecting Class 01 and Class 05 (2 marks)**
Blanks = **PYTHON CODE** then **RUN** (in that order). The one-sentence
explanation should convey that Class 05 turned Class 01's abstract
`ALGORITHM → PROGRAM` step into something real — writing actual Python
code and running it to get the result — without changing anything else
about Class 01's chain.

**Q12 — Write Your Own Program (3 marks)**
Accept any coherent program with at least three `print()` lines and at
least one comment, on any topic the student chooses. Check for: (1) the
program is syntactically plausible — quotes matched, `print` spelled and
capitalized correctly, (2) a comment is present, (3) the explanation
correctly frames an error as a normal, expected part of writing code —
not a sign of failure. (1 mark for a valid three-line-plus-comment
program; 2 marks for a sound explanation of why errors are normal.)

**Optional Challenge (up to 3 bonus marks)**
The three bugs: (1) the first `print()` line is missing its closing
quote after `Python!`; (2) `Print` on the second line is capitalized and
should be lowercase `print`; (3) the last line's comment itself has an
unmatched opening quote/unclosed parenthesis inside the commented-out
text — accept either "it's harmless because the whole line is already a
comment" or a corrected version as reasoning, since the line never runs
either way. Corrected program:
```

print("Hi, I'm learning Python!")
print("This is my second line.")
print("This is my third line.")
# print("This line won't show up — why?")
```
1 mark per correctly identified and fixed bug. Do not deduct marks if a
student flags the third line's stray characters as "not actually a bug
since it's a comment and never runs" — that is an equally valid,
arguably stronger, answer.
