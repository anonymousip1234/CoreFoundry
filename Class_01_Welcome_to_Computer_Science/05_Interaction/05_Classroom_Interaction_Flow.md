# Class 01 — Classroom Interaction Flow

**Bong Study Hub — Foundation Batch 2026 · Welcome to Computer Science**

A minute-by-minute interaction map for the 110-minute class, plus
strategies for quiet students, overactive students, wrong answers,
silence, and the online classroom. Timing matches the Master Instructor
Guide §4 and the Pen-Tablet Board Plan §4 exactly — this document adds
*interaction texture* on top of that timing, it does not change it.

**Mode legend:** `HIGH` = high interaction · `LOW` = low interaction ·
`REFLECT` = reflection · `EXPLAIN` = explanation · `ACTIVITY` = structured
activity. Most segments are tagged with two modes (e.g., `EXPLAIN → HIGH`)
to show the shift within the segment.

## Part A — The 110-Minute Interaction Map

### 0–3 min · Opening warm-up · `HIGH`
- **Teacher action:** Ask "how many of you used a smartphone / a computer
  today?"; ask "who's never written a line of code — no judgment?"
- **Student action:** Raise hands; a few may call out.
- **Question:** Q1.1, Q1.3 (Question Bank).
- **Expected interaction:** Broad, low-effort participation — hands, not
  words yet.
- **Board action:** None.
- **Slide action:** Title slide only.
- **Transition:** "We're going to start understanding what's actually
  happening today."

### 3–8 min · "What is Computer Science?" (collecting) · `HIGH`
- **Teacher action:** Ask Q1.2; collect 3–5 answers without correcting
  any of them.
- **Student action:** Call out words: coding, AI, software, computers.
- **Question:** Q1.2.
- **Expected interaction:** 4–6 distinct student voices.
- **Board action:** None yet (words are just verbally repeated/held).
- **Slide action:** None.
- **Transition:** "Let's use exactly what you just said to build a map."

### 8–9 min · CS definition · `LOW / EXPLAIN`
- **Teacher action:** Say the one-line CS definition once, plainly.
- **Student action:** Listen.
- **Question:** None.
- **Expected interaction:** None expected — this is a calm anchor moment.
- **Board action:** Slide only (title circle).
- **Slide action:** "Computer Science" in a plain circle.
- **Transition:** "Let's put your answers on this map."

### 9–17 min · CS Map (Drawing 1) · `HIGH / ACTIVITY`
- **Teacher action:** Build the CS map live from student answers, then add
  2–3 fields nobody said. Ask Q2.1.
- **Student action:** Watch the map grow; answer Q2.1; copy the finished
  map.
- **Question:** Q2.1, Q2.2.
- **Expected interaction:** Whole-class, several short answers.
- **Board action:** Full Drawing 1 sequence (Board Plan Drawing 1).
- **Slide action:** Minimized once drawing starts.
- **Transition:** "Now that we've mapped the field, let's zoom into one
  question: how does a computer actually solve something?" *(Board Plan
  §7 bridging line)*

### 17–21 min · CS map debrief · `HIGH / REFLECT`
- **Teacher action:** Ask Q2.2, optionally Q2.3 for stronger students.
- **Student action:** Discuss whether coding is all of CS.
- **Question:** Q2.2, Q2.3.
- **Expected interaction:** 2–4 answers, at least one Challenge-level.
- **Board action:** Map stays visible (minimized corner).
- **Slide action:** None.
- **Transition:** Into the Like-button hook / Computer-Program-Application
  vocabulary.

### 21–25 min · "What happens when we use technology?" hook · `LOW / EXPLAIN`
- **Teacher action:** Trace the Like-button example conceptually (User →
  Device → App → Network → Server → Database → Response → Device).
- **Student action:** Listen; react to "wait, all of that happens?"
- **Question:** None required — this is a hook, not a Q&A block.
- **Expected interaction:** Reactive murmurs, not structured answers.
- **Board action:** None (optional quick slide list).
- **Slide action:** Optional list slide.
- **Transition:** "Let's get precise vocabulary for three of those words."

### 25–29 min · Computer / Program / Application definitions · `LOW / EXPLAIN`
- **Teacher action:** State the three definitions; give examples
  (calculator, browser, game, messaging app, AI chatbot).
- **Student action:** Listen; glance at slide reference.
- **Question:** None yet.
- **Expected interaction:** Low — this block is intentionally a slide
  reference (Board Plan §5, "Why This Is Live").
- **Board action:** None.
- **Slide action:** Three definitions, visible and clean.
- **Transition:** "Let's test that with a question."

### 29–33 min · Computer/Program/App application · `HIGH`
- **Teacher action:** Ask Q3.1, Q3.2, Q3.3 as time allows.
- **Student action:** Answer; discuss "program vs. application."
- **Question:** Q3.1–Q3.3.
- **Expected interaction:** 3–5 answers across the room.
- **Board action:** None.
- **Slide action:** Definitions slide stays up.
- **Transition:** "That 'Process' box was a mystery box. Let's open the
  idea of Input → Process → Output." *(Board Plan §7)*

### 33–39 min · Input → Process → Output (Drawing 2) · `HIGH / ACTIVITY`
- **Teacher action:** Build Drawing 2 live; ask Q4.1, Q4.2.
- **Student action:** Answer; copy the 3-box skeleton + calculator
  example.
- **Question:** Q4.1, Q4.2.
- **Expected interaction:** Whole-class, quick-fire.
- **Board action:** Full Drawing 2 sequence.
- **Slide action:** Minimized.
- **Transition:** "Now find your own example, in pairs."

### 39–43 min · IPO pair activity (Activity 2) · `HIGH / ACTIVITY`
- **Teacher action:** Run Activity 2 (90-second pair task); cold-call 2–3
  pairs.
- **Student action:** Discuss in pairs; 2–3 pairs share aloud.
- **Question:** Q4.3 (for shared examples, as relevant).
- **Expected interaction:** 100% of room active (in pairs), 2–3 pairs
  speak to whole class.
- **Board action:** None (pair work is verbal).
- **Slide action:** None.
- **Transition:** "Giving a computer instructions to fill that Process box
  is called programming — and it starts with a bigger chain than three
  boxes." *(Board Plan §7)*

### 43–56 min · Problem→Logic→Algorithm→Program→Result + "Build an Algorithm" (Drawing 3 / Activity 4) · `HIGH / ACTIVITY` — PROTECTED
- **Teacher action:** Build the 5-box chain one link at a time, each
  earned by a question (Q5.1–Q5.4); build the "larger of two numbers"
  algorithm live from student answers (Activity 4).
- **Student action:** Answer each `[ASK]`; supply algorithm steps; copy
  the finished chain — highest-priority copy of the class.
- **Question:** Q5.1–Q5.4, Q6.1.
- **Expected interaction:** Continuous — this segment is built almost
  entirely from student answers, not lecture.
- **Board action:** Full Drawing 3 sequence (Board Plan Drawing 3,
  Stages 1–9).
- **Slide action:** None — fully blank canvas.
- **Transition:** "Before you can turn a problem into an algorithm, you
  need a certain way of thinking. Let's name what you just did."

### 56–59 min · Algorithm ≠ Program · `LOW / EXPLAIN`
- **Teacher action:** State the algorithm-vs-program distinction; jot the
  "recipe/dish" note.
- **Student action:** Answer Q6.2, Q6.3 if time allows.
- **Question:** Q6.2, Q6.3.
- **Expected interaction:** 1–2 answers; mostly consolidation.
- **Board action:** Two-word note under Drawing 3 (Stage 9, optional).
- **Slide action:** Full comparison table reference (already in Student
  Notes).
- **Transition:** "Algorithmic thinking is exactly what you're about to
  try, live — on me." *(bridges toward Computational Thinking)*

### 59–67 min · Computational Thinking (Drawing 4) · `HIGH / ACTIVITY`
- **Teacher action:** Build the 2×2 grid one quadrant at a time, question
  first (Q7.1–Q7.3).
- **Student action:** Answer each question; copy all four quadrants.
- **Question:** Q7.1–Q7.4.
- **Expected interaction:** Whole-class, one exchange per quadrant.
- **Board action:** Full Drawing 4 sequence.
- **Slide action:** Empty 2×2 grid outline pre-drawn.
- **Transition:** "Algorithmic thinking is exactly what you're about to
  try, live — on me." *(Board Plan §7)*

### 67–71 min · Computational Thinking reflection · `REFLECT`
- **Teacher action:** Ask "you already used all four of these today
  without realizing it — which was your favorite?"
- **Student action:** Brief personal reflection, 1–2 answers.
- **Question:** Q7.4.
- **Expected interaction:** Light, low-pressure.
- **Board action:** Grid stays visible.
- **Slide action:** None.
- **Transition:** Into the tea activity setup.

### 71–73 min · Tea activity opening + rules · `LOW / EXPLAIN`
- **Teacher action:** Deliver the opening line and rules exactly as in
  `03_Tea_Activity_Facilitator_Guide.md`.
- **Student action:** Listen; one volunteer prepares.
- **Question:** None yet.
- **Expected interaction:** Low — this is framing, not participation yet.
- **Board action:** None.
- **Slide action:** None (camera/title card only).
- **Transition:** Directly into Round 1.

### 73–83 min · Tea activity — Rounds 1 & 2 · `HIGH / ACTIVITY` — PROTECTED
- **Teacher action:** Role-play the literal computer; ask clarifying
  questions per the Facilitator Guide's table; deliver the "no gas"
  escalation partway through.
- **Student action:** Give instructions one step at a time; react to
  gaps; 2–3 students rotate through as instruction-giver.
- **Question:** In-character clarifying questions (Facilitator Guide),
  not the Question Bank.
- **Expected interaction:** Sustained, high-energy, whole class engaged
  as audience even when not speaking.
- **Board action:** None.
- **Slide action:** None.
- **Transition:** Directly into debrief.

### 83–86 min · Tea activity debrief + key lesson · `REFLECT`
- **Teacher action:** Ask Q8.1–Q8.3; deliver the key lesson line.
- **Student action:** Answer; absorb the key lesson.
- **Question:** Q8.1–Q8.3.
- **Expected interaction:** 3–4 answers, building to the key lesson.
- **Board action:** None.
- **Slide action:** None.
- **Transition:** "That gap between what you meant and what you actually
  said is exactly what separates how we've been programming from
  something newer." *(Board Plan §7)*

### 86–90.5 min · Traditional/ML/GenAI (Drawing 5) · `HIGH / ACTIVITY`

- **Student action:** Answer; copy all three rows.
- **Question:** Q9.1, Q9.2.

- **Expected interaction:** Low — closing information.
- **Board action:** None.

## Part B — Quiet Students

Use these strategies rather than direct cold-calling on a silent room —
they involve everyone without forcing anyone:

- **Think-pair-share:** Give 30–60 seconds of individual thinking, then
  pair discussion, before any whole-class sharing. This is built into
  Activity 2 and works for most Question Bank items.
- **Write-first:** For any recap-style question, ask students to jot one
  word or one sentence before anyone speaks — removes the pressure of
  "first to answer."
- **Random-but-friendly selection:** Use a visible, neutral method (a
  name picker, or simply going in roll-call order) rather than always
  calling on whoever's hand is fastest — signals that everyone is equally
  likely to be asked, which paradoxically makes volunteering feel safer.
- **Polling:** For binary or multiple-choice-shaped questions ("is coding
  all of CS, or one part of it?"), use a quick show-of-hands or an online
  poll instead of requiring a spoken answer.
- **Chat responses (online):** Invite typed answers in chat as a lower-
  pressure alternative to unmuting — read 2–3 aloud, crediting the
  student by name.
- **Small group discussion:** For heavier questions (Challenge-level, or
  the ATM optional activity), 3–4 person breakout groups let quieter
  students test an answer before it's public.

**Never** force a specific silent student to answer by name unprompted,
and never comment on someone's silence in front of the class.

## Part C — Overactive Students

Goal: preserve their enthusiasm, don't let it crowd out the room.

- Acknowledge the answer warmly, then explicitly redirect: "great — let's
  hear a different voice on this one" or "I want to bank that idea, let's
  see what else is out there first."
- Give them a specific role: "you're my challenge-question person today —
  I'll come to you when we get to the harder version."
- After 2–3 quick wins from the same student, shift the question format
  to think-pair-share or chat/poll, which structurally distributes
  participation without singling anyone out.
- If it persists, a quiet 1:1 word at a natural break ("I love your
  energy — help me pull other people in too") works better than a public
  correction.
- Never say "let someone else answer" in a tone that could read as a
  rebuke — frame it as wanting more voices, not as them talking too much.

## Part D — Wrong Answers: Response Patterns

Never say "no, that's wrong." Use one of these instead:

1. "Interesting — what makes you think that?"
2. "Let's test that idea against an example."
3. "Would that work in every case?"
4. "You're onto something — what's the piece that's still missing?"
5. "Close — what would happen if we tried that on [a slightly different
   example]?"
6. "That's a common first instinct — let's poke at it together."
7. "Say more about that — I want to understand your reasoning."
8. "Half right — which part do you feel most sure about?"
9. "Good guess. What's another way to look at it?"
10. "That's actually what most people think coming in — that's exactly
    what we're about to untangle."

The shared move behind all ten: treat the answer as a hypothesis to test,
not a verdict to deliver. Always let the *class* or a follow-up example
reveal the gap — don't announce it yourself.

## Part E — Silence

**The 3-second rule:** After asking a question, count silently to three
before doing anything else. Most instructors fill silence after
half a second out of discomfort — three real seconds feels much longer to
the instructor than it does to the room, and it's usually enough time for
a hand to go up.

If silence continues past 3 seconds:
- Rephrase the question once, more concretely (add an example or narrow
  the scope) — don't just repeat it louder.
- If still silent, use think-pair-share: "take 20 seconds, turn to the
  person next to you" — this almost always breaks a silent room.
- **Do not answer your own question.** If the room truly can't produce an
  answer after a rephrase and a pair-discussion, ask a more scaffolded
  version ("is it more like X, or more like Y?") rather than supplying
  the answer outright.

## Part F — Online Classroom Strategies

This program runs online. Interaction has to be redesigned for a screen,
not just transplanted from an in-person room.

### General adaptations

- **Microphones off by default:** Ask students to unmute only when
  answering; use "raise hand" (physical or platform reaction) to queue
  speakers rather than talking over each other.
- **Chat responses:** For any question where you'd accept a one-word or
  one-line answer, explicitly invite chat responses as equally valid to
  unmuting — read a few aloud by name.
- **Screen sharing:** Keep the shared screen to the slide/board only when
  actively teaching a concept; switch to camera view (or a simple title
  card) during the tea activity and open discussion so students see faces
  and energy, not a static board.
- **Students joining late:** Have a single pinned chat message with "what
  we've covered so far" (updated at each section transition) so latecomers
  can self-orient without a verbal recap interrupting the room.
- **Poor internet:** Never require a specific student to have working
  video for participation to count — chat and audio-only answers are
  always acceptable; repeat any spoken instruction in chat as backup.
- **Reluctant speakers:** Lean harder on chat-based think-pair-share and
  polls (Part B) — online reluctance is often about not wanting to be the
  only unmuted voice, which chat/poll formats sidestep entirely.

### 10–15 students

- Cold-calling is viable in moderation — the group is small enough that
  most students speak at least once naturally across 110 minutes.
- Breakout pairs for Activity 2 can be manual (instructor assigns pairs
  verbally) without needing formal breakout-room tooling.
- The tea activity can rotate through 2–3 volunteers with the whole group
  watching live on camera — intimate enough that side-chatter is rare.

### 25–30 students

- Avoid cold-calling by name except at planned moments (e.g., the final
  recap) — with this many students, rely primarily on chat, polls, and
  breakout rooms so participation scales without single students being
  put on the spot repeatedly.
- Use actual breakout rooms (not just verbal pairing) for Activity 2 and
  the optional ATM activity — manually pairing 25–30 students verbally
  wastes time.
- For the tea activity, cap volunteers at 2 (per the Facilitator Guide's
  online adaptation) and actively use chat as a second interaction
  channel: "everyone else, type what question you think I'll ask next."
- Expect slightly longer transition times between segments (muting/
  unmuting, breakout room shuffling) — budget an extra 1–2 minutes total
  across the class for this in a large-group session; absorb it from the
  shortenable sections (Guide §4.1), never from Drawing 3 or the tea
  activity.

## Part G — 90-Minute Compressed Interaction Strategy

Follow the Guide §4.3 and Board Plan §4 compression exactly — every
*shortenable* section drops to its Min value. For interaction specifically:

- Keep every `[ASK]` moment in Drawings 3 and the tea activity — these are
  protected and untouched.
- In all other segments, reduce to **one** question-and-answer exchange
  per concept instead of two or three (e.g., Q2.1 only, skip Q2.2/Q2.3
  unless a student raises the idea unprompted).
- Cut Activity 2 (IPO pair activity) to a single instructor-led example
  instead of a pair task if time is genuinely tight — but prefer cutting
  the optional ATM activity first (it's already marked optional).
- Skip the Like-button hook entirely (Guide §4.3, cut order item 3).
- Recap (Part A, 102–108 min) stays at all 5 questions — never compressed,
  per Guide §4.1 marking Section 10 "No — core close."

## Part H — 120-Minute Expanded Interaction Strategy

Follow Guide §4.2 and Board Plan §4 — the extra time goes into Sections
2, 3, and 6 (CS Map, Computer/Program/Application, Computational
Thinking). For interaction specifically:

- Ask **all** listed questions per section instead of a subset (e.g., all
  three CS Map questions, not just Q2.1–Q2.2).
- Add one additional think-pair-share round before the Computational
  Thinking quadrants (60 seconds: "with a partner, guess what the four
  quadrants might be called before I reveal them") — this is pacing, not
  new content.
- Let the tea activity run its optional second escalation (Facilitator
  Guide, "Optional second escalation") if the room's energy supports it.
- Do not add a new activity or a new question topic — the extra time
  buys more voices per question, not more questions per concept.
