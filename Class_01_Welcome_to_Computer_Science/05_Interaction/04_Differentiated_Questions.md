# Class 01 — Differentiated Questions

**Bong Study Hub — Foundation Batch 2026 · Welcome to Computer Science**

The room contains students who have never coded and students who already
know Python. This file gives every concept in Class 1 three entry points
— **Foundation**, **Builder**, **Challenge** — so both ends of the room
stay engaged without the class ever feeling like two different lessons.

## Ground Rules

- **Never say the words "Foundation," "Builder," or "Challenge" out loud
  to the room**, and never assign a question to a specific student by
  perceived ability. Offer questions naturally as discussion allows, and
  let students self-select by which one they choose to answer.
- **Challenge questions deepen today's concepts — they never jump ahead.**
  Nothing below introduces DSA, complexity, data structures, or real
  syntax. A Challenge question about the "larger of two numbers" algorithm
  stays about that algorithm; it does not turn into a sorting-algorithm
  discussion.
- **A student who only answers Foundation questions all class has still
  succeeded.** The class's seven success criteria (Guide §10) do not
  require Challenge-level answers from anyone.
- **Use these to widen a discussion, not to gate it.** A natural pattern:
  ask the Foundation version first to warm up the room, then immediately
  follow with the Builder or Challenge version to the same question for
  whoever wants to go further.

## 1. Computer Science / The CS Map

| Level | Question |
|---|---|
| Foundation | "Name one thing that's part of Computer Science besides coding." |
| Foundation | "Which of these have you already touched without realizing it was Computer Science?" |
| Builder | "Which part of the map do you think you'd enjoy learning most, and why?" |
| Builder | "If Computer Science were only coding, where would AI, networks, or databases fit?" |
| Challenge | "Could something on this map belong to more than one area at once? Give an example." |
| Challenge | "Pick two areas on the map — how might they depend on each other?" |

## 2. Computer / Program / Application

| Level | Question |
|---|---|
| Foundation | "What is a program, in your own words?" |
| Foundation | "Is a calculator app a program, an application, or both?" |
| Builder | "Name an app you use daily that's clearly built from several smaller programs working together." |
| Challenge | "What's the smallest possible 'program' you can imagine — something with almost no real use but it still counts?" |

## 3. Input → Process → Output

| Level | Question |
|---|---|
| Foundation | "What is an input?" |
| Foundation | "What is an output?" |
| Builder | "Give your own input–process–output example, different from the calculator." |
| Builder | "Can you identify input, process, and output in an ATM?" |
| Challenge | "Can a system have more than one input feeding the same process? Give an example." |
| Challenge | "What do you think is actually happening inside a 'process' box you can't see into — take a guess, we won't check it yet." |

## 4. Problem → Logic → Algorithm → Program → Result

| Level | Question |
|---|---|
| Foundation | "What's a real problem you'd like a computer to help solve?" |
| Foundation | "Which comes first — logic or algorithm?" |
| Builder | "Why can't we skip straight from a problem to a program?" |
| Challenge | "Could two different algorithms solve the same problem, and both be correct?" |
| Challenge | "What has to stay the same, and what's allowed to change, as you move from algorithm to program?" |

---

## 5. Algorithm

| Level | Question |
|---|---|
| Foundation | "What does an algorithm mean to you?" |
| Foundation | "Can you create an algorithm for finding the larger of two numbers?" |
| Builder | "Which one is the 'recipe' and which is the 'dish' — algorithm or program?" |
| Builder | "Could the same algorithm be written in two different programming languages? What stays the same, what changes?" |
| Challenge | "How would your algorithm behave if both numbers are equal?" |
| Challenge | "What assumptions does your algorithm make?" |
| Challenge | "How would you make the algorithm work for three numbers instead of two?" |

*(These three Challenge questions are the program's recommended default
set — they deepen the exact same algorithm rather than introducing a new
one.)*

## 6. Computational Thinking

| Level | Question |
|---|---|
| Foundation | "What does 'breaking a big problem into smaller ones' mean to you?" |
| Foundation | "When you drive a car, do you think about the engine, or just 'accelerator = go'?" |
| Builder | "Pick a daily task and decompose it into 3–4 smaller steps." |
| Builder | "What's similar between comparing two numbers and comparing two people's height?" |
| Challenge | "Find a pattern connecting two problems that look unrelated on the surface (e.g., finding a book on a shelf vs. finding a contact in your phone)." |
| Challenge | "Which of today's earlier activities was already an example of algorithmic thinking?" |

## Using These in the Moment

A simple three-beat pattern that works for almost any concept above:

1. Ask the **Foundation** version to the whole room — low pressure, high
   participation.
2. After 1–2 answers, ask **"can anyone push that further?"** and offer
   the **Builder** version — this naturally pulls in students who were
   holding back a more developed thought.
3. If the room has energy and time, close with the **Challenge** version
   as an open floor, not a cold call — this keeps it opt-in for students
   who want the stretch, without pressuring anyone.

This mirrors the teaching loop in `05_Classroom_Interaction_Flow.md`:
ASK → student thinks → student answers → discussion → instructor guides →
board/visual → concept → application.
