# Assignment 1 — Reusable Instructor Feedback Comments

**Bong Study Hub — Foundation Batch 2026 · Class 01: Welcome to Computer Science**

Copy, paste, and lightly personalize (name the specific input/step where
useful). Tone throughout is encouraging and constructive — this is a
beginner's first assignment in the program, not an exam. Never use these
to shame a wrong answer; every comment below treats a gap as something to
build on, not a failure.

## Input

1. "Good identification of inputs."
2. "You've got the main inputs — see if you can spot one more thing the
   process would actually need before it can start."
3. "Careful: [X] you listed is really something that happens *during* the
   process, not something needed *before* it starts."

## Process

4. "Your process is correct, but some steps are missing."
5. "Nice job breaking the process into stages — that's exactly the
   decomposition skill from class."
6. "Your process description is a little vague — try describing what
   actually happens, not just that 'it happens.'"

## Output

7. "Clear, specific output — exactly what we're looking for."
8. "Your output is a bit general. What does 'done' actually look like at
   the end?"

## Algorithm — Clarity & Sequence

9. "Good algorithm. Notice how you solved the problem without writing
   code."
10. "Your steps are logical, but double-check the order — step [X] seems
    to need to happen before step [Y]."
11. "Try making each step more precise."
12. "This step does two things at once — consider splitting it into two
    steps."

## Precision / Completeness

13. "Think about what happens if the expected condition fails."
14. "Would a stranger be able to follow this without guessing anything?
    Check for one place where they might get stuck."
15. "You're assuming [X] is already true — is that always the case?"

## General Encouragement / Closing

16. "This is exactly the kind of precise thinking programming requires —
    well done."
17. "You're thinking like a programmer already — this is the hardest
    part, and you did it without any code."
18. "Solid first attempt. Revisit the self-check list before your next
    submission and you'll catch most of this yourself."

## Optional Challenge (use only if attempted)

19. "Great instinct adding a decision point — that's exactly what
    'if this, then that' looks like before we ever write real code."
20. "Nice work spotting an edge case most people would miss."

---

## How to Combine Comments

A typical piece of feedback uses **one positive comment + one
improvement suggestion**, per the grading workflow (see
`05_Instructor_Grading_Workflow.md`, Step 5–6). For example:

> "Good identification of inputs. Your process is correct, but some
> steps are missing — think about what happens right after you confirm
> the order."

Keep total written feedback to 1–3 sentences per submission. The goal is
a quick, warm, specific nudge — not a rewrite of the student's work.
