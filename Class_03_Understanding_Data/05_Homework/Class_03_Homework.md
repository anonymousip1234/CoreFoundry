## What This Assignment Is About

In class, we opened a box Class 02 left closed: **data**. We saw that
data is just recorded information about something — not only numbers —
and that it comes from the real world through observation and
recording:

```
REAL WORLD → OBSERVATION → DATA
```

We looked at examples, datasets, rows, columns, features, and labels,
and we saw that more data isn't automatically better data, and that
useful data always depends on the question being asked.

This assignment asks you to **use these ideas, not recite them**. There
is no coding, no math beyond everyday counting, and no single
"correct sentence" to memorize — if your reasoning makes sense, your
answer is good, even if it doesn't use the exact words from class.

## Answers

**Q1 — What Is Data?**
Data is recorded information about something. Any phrasing that
captures "recorded" + "information" + "about something real" earns
full marks.

**Q2 — Data Is Not Just Numbers**
Any valid non-numeric examples, such as a photograph, an audio/voice
recording, a piece of text, a location, or a written record — full
credit for any three with a reasonable "what it represents" note.

**Q3 — From Reality to Data**
Real world = the rain/weather event itself. Observation = noticing or
checking that it's raining. Recorded data = the information written
down, said aloud, or otherwise saved (e.g., "it's raining," a weather
app reading). The observation becomes data once it is **recorded** in
some form that can be stored or worked with later.

**Q4 — Representation of Reality**
No. "80% full" is a recorded representation/description of the
crowded canteen — not the physical canteen itself. Every representation
leaves something out.

**Q5 — Read the Table**
a. One student / one example.
b. One kind of information (attendance), recorded across all examples.
c. Three examples.
d. It is a collection of related examples — that's the definition of a
dataset.

**Q6 — Build Your Own Tiny Dataset**
Accept any coherent, fictional 3-row, 3–4-column dataset on a
reasonable theme. Check that the student can correctly state: one row
= one example; one column = one kind of information shared across all
examples. The visual polish of the table does not matter — the
structural understanding does.

**Q7 — Feature or Label?**
a. Any two of: the email text, the sender, the time — these are
features.
b. Spam.
c. Not Spam.
d. No — not every dataset has a label; some datasets are only examples
described by features.

**Q8 — The Canteen Problem**
Multiple reasonable answers are expected (e.g., time of day, day of
the week, number of students on campus, whether there's a class break,
weather, past crowd patterns). Credit the reasoning connecting the
chosen item to canteen crowding, not whether it matches this list.

**Q9 — Change the Question**
Multiple reasonable answers (e.g., genre, reviews, previous ratings,
favorite actors, mood). The core point to check for: the student
recognizes that useful information changes when the question changes,
and can explain that canteen-crowding data (time, traffic, weather)
doesn't obviously relate to movie taste.

**Q10 — More Data ≠ Better Data**
Dataset B — because accuracy and useful variety matter more than raw
quantity; a huge pile of wrong or repetitive examples doesn't become
useful just by being large.

**Q11 — Spot the Mess**
Any two or more of: a missing value (Student C's age), an inconsistent
representation of the same information (age written as "eighteen"
instead of 18), inconsistent naming (Kolkata / kolkata / Calcutta all
referring to the same city). Do not expect or require a fix — only
recognition.

**Q12 — Connect Class 02 and Class 03**
Blank = **OBSERVATION**. The explanation should convey that Class 03
added `REAL WORLD → OBSERVATION → DATA` *before* the Class 02 pipeline
`DATA → LEARNING → MODEL → PREDICTION` — i.e., it explained where data
actually comes from, rather than changing anything about Class 02's
pipeline itself.

**Optional Challenge**
No fixed answer. Evaluate based on the quality of reasoning connecting
candidate information to event attendance (e.g., past attendance at
similar events, timing/day, whether it clashes with exams) versus
information that sounds plausible but likely isn't relevant (e.g., a
student's favorite color, shoe size). Do not expect or reward any
formal feature-engineering or ML vocabulary — this stays at the level
of "question → useful data" reasoning established in class.
